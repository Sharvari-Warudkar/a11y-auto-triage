# WCAG 2.1 Success Criterion 3.3.2: Labels or Instructions (Level A)

## Requirement
Labels or instructions are provided when content requires user input.

## Who is affected
- Users with cognitive disabilities who need clear instructions
- Screen reader users who need labels to understand form fields
- Users with low vision who may miss placeholder text when it disappears
- Older users unfamiliar with conventions (e.g., date format)

## Common failures
- Using only placeholder text as the label (disappears on input)
- Form fields with no visible label or instruction
- Required fields not indicated before the form
- Format requirements not communicated (e.g., date must be MM/DD/YYYY)
- Groups of related fields (like address) without group label

## Sufficient techniques
- H44: Using label elements to associate text labels with form controls
- H71: Providing a description for groups of form controls using fieldset and legend
- G131: Providing descriptive labels
- ARIA1: Using the aria-describedby property to provide a descriptive label for input

## Remediation
1. Add visible, persistent labels above or beside every form input
2. Don't rely on placeholder text as the only label — it disappears on focus
3. Use fieldset/legend for groups of related controls (address, payment info)
4. Indicate required fields with both visual marker (*) and programmatic (aria-required)
5. Provide format instructions adjacent to fields that need specific formats
6. Use aria-describedby to associate additional instructions with inputs
