# WCAG 2.1 Success Criterion 1.3.1: Info and Relationships (Level A)

## Requirement
Information, structure, and relationships conveyed through presentation can be programmatically determined or are available in text.

## Who is affected
- Screen reader users who cannot see visual formatting cues
- Users who apply custom stylesheets
- Users with cognitive disabilities who rely on consistent structure

## Common failures
- Using visual formatting instead of semantic HTML (e.g., bold text instead of headings)
- Tables without proper header cells (th) or scope attributes
- Form inputs without associated labels
- Lists not marked up as ul/ol/li
- Heading levels that skip (h1 → h3)

## Sufficient techniques
- H44: Using label elements to associate text labels with form controls
- H51: Using table markup to present tabular information
- H48: Using ol, ul, and dl for lists or groups of links
- H42: Using h1-h6 to identify headings
- ARIA11: Using ARIA landmarks to identify regions of a page

## Remediation
1. Use semantic HTML elements (headings, lists, tables) instead of visual-only formatting
2. Associate all form inputs with labels using the 'for' attribute
3. Add scope attributes to table headers (scope="col" or scope="row")
4. Use ARIA landmarks (main, nav, aside, footer) to identify page regions
5. Maintain logical heading hierarchy without skipping levels
