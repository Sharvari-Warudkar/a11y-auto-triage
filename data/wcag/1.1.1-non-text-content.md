# WCAG 2.1 Success Criterion 1.1.1: Non-text Content (Level A)

## Requirement
All non-text content that is presented to the user has a text alternative that serves the equivalent purpose.

## Exceptions
- Controls/Input: If non-text content is a control or accepts user input, it has a name that describes its purpose.
- Decoration/Formatting/Invisible: If non-text content is pure decoration, used only for visual formatting, or not presented to users, it is implemented so assistive technology can ignore it.

## Who is affected
- Blind users who use screen readers
- Users with low vision who use text enlargement
- Users with cognitive disabilities who benefit from text descriptions
- Users on slow connections who disable images

## Common failures
- Images without alt attributes
- Informative images with empty alt=""
- Images with non-descriptive alt text (e.g., "image", "photo", "graphic")
- Background images that convey information without text alternative
- CAPTCHA without text alternatives

## Sufficient techniques
- H37: Using alt attributes on img elements
- H67: Using null alt text and no title attribute for images that assistive technology should ignore
- ARIA6: Using aria-label to provide labels for objects
- ARIA10: Using aria-labelledby to provide a text alternative for non-text content

## Remediation
1. Add descriptive alt text to all informative images
2. Use alt="" (empty) only for truly decorative images
3. For complex images (charts, diagrams), provide long descriptions
4. Ensure all form inputs have accessible names
