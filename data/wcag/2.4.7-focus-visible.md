# WCAG 2.1 Success Criterion 2.4.7: Focus Visible (Level AA)

## Requirement
Any keyboard operable user interface has a mode of operation where the keyboard focus indicator is visible.

## Who is affected
- Keyboard-only users (mobility impairments)
- Users with low vision who need to see where focus is
- Users with cognitive disabilities who lose track of position
- Power users who navigate with keyboard for speed

## Common failures
- CSS outline: none without a replacement focus style
- Focus styles that have insufficient contrast against the background
- Focus styles only visible on some interactive elements, not all
- Focus trapped in elements users cannot see
- Custom components that don't show focus at all

## Sufficient techniques
- G149: Using user interface components that are highlighted by the user agent when they receive focus
- G165: Using the default focus indicator for the platform
- G195: Using an author-supplied, highly visible focus indicator
- C15: Using CSS to change the presentation of a UI component when it receives focus

## Remediation
1. Never use outline: none without providing an alternative visible focus indicator
2. Use :focus-visible pseudo-class for modern browsers (shows focus on keyboard nav only)
3. Ensure focus indicator has at least 3:1 contrast against adjacent colors
4. Test by tabbing through the entire page — every interactive element should show focus
5. Consider using a focus ring that is at least 2px solid with a contrasting color
6. Custom components (custom dropdowns, tabs, modals) must manage focus visibility
