# WCAG 2.1 Success Criterion 3.1.1: Language of Page (Level A)

## Requirement
The default human language of each web page can be programmatically determined. Set a valid `lang` attribute on the `html` element (for example `<html lang="en">`) so that assistive technology uses the correct pronunciation rules.

## Who is affected
- Blind users and users of screen readers, which choose a speech voice and pronunciation from the page language
- Users with cognitive and learning disabilities who rely on text-to-speech
- Users of braille displays, which select the correct braille translation table
- Users of translation and spell-check tools

## Common failures
- The `html` element has no `lang` attribute
- The `lang` attribute is empty or not a valid language code (for example `lang="english"`)
- The `lang` value does not match the language of the page content
- A page template reused across locales always declares the same language

## How to measure
- Inspect the `html` element for a valid `lang` attribute using BCP 47 codes such as `en` or `fr-CA`
- Tools: axe-core rules `html-has-lang` and `html-lang-valid`, browser DevTools

## Sufficient techniques
- H57: Using the language attribute on the HTML element
- Failure F: pages whose `html` element lacks a valid language attribute

## Remediation
Add the attribute to the root element, for example change `<html>` to `<html lang="en">`. For multilingual pages, set the primary language on `html` and mark passages in other languages with their own `lang` attribute (see 3.1.2).
