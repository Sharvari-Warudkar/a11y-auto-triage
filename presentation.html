Problem & Solution

The Problem

  • ~45 minutes per page to manually write accessibility bug tickets
  • Tickets lack remediation guidance — developers ask follow-up questions
  • No deduplication — same violations filed repeatedly across sprints
  • Inconsistent severity across QA engineers

Definition of Success

Reduce per-page triage to <5 min, with ≥85% correct WCAG criterion citations and code-level fix suggestions.

The Solution

Sample Bug Log (Real Output)

Critical Missing Image Alt Text

WCAG 1.1.1 — Non-text Content

Selector: img[src$="shoe-red.jpg"]

Affected: blind users, low vision, cognitive disabilities, slow connections

Fix: Add descriptive alt text to all informative images, or use alt="" for decorative images.

Minor Insufficient Color Contrast

WCAG 1.4.3 — Contrast (Minimum)

Selector: .product-card > p

Affected: low vision, color deficiency, older users

Actual ratio: 2.32:1 (needs 4.5:1)

Fix: Increase text darkness or lighten background to achieve 4.5:1

Key finding: The pipeline can only report what axe-core detects. Our checkout form has 8 inputs without proper labels, but axe-core accepts placeholder text as a sufficient name. This is a real limitation — we report 2 violations on checkout.html when a manual audit would find 8+.

Context Engineering & Test Suite

CLAUDE.md Effect (observed)

The system prompt in generate.ts uses rules from CLAUDE.md:

CLAUDE.md RuleObserved Effect in Output
Severity mapping (critical/major/minor/trivial)All 11 reports use the defined scale consistently
Citation format ("1.4.3" not "WCAG 1.4.3")10/10 parsed reports use correct format
Checkout = critical priorityNot followed for contrast: "major" with and without CLAUDE.md (controlled run)

Where it didn't help

CLAUDE.md says "specific attribute/property to change" — but contrast violations still get generic suggestions. The LLM can't calculate passing colors without a tool.
